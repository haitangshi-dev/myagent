# task-templates — 高频任务管线模板库

> 用途：把反复摸索的「下载→解析→入库→发邮件→写记忆」类管线沉淀为可复用模板。
> 遇到相似任务时，先 `use_skill task-templates`，按模板走，不要从零摸索。

---

## 模板 1：数据抓取入库管线（kb_download_pipeline）

适用：抓取网页/API 数据 → 解析 → 入库（JSONL/JSON 文件）→ 写记忆 → 可选发邮件汇报。

**步骤**：

1. **下载**：用 `http_request`（网页）或 `download`（文件）工具。
   - 优先带默认浏览器头（框架已自动注入）；遇到 HTTP 567/403/429 说明被反爬拦截：
     - 567 → EdgeOne/WAF 拦截：换数据源、或补 `Referer`/`Cookie` 头、或稍等重试
     - 429 → 限流：加 `delay` 参数（如 `delay=[2,5]`）放慢频率
   - 长响应（>50KB）框架会自动完整落盘并返回路径，用 `read_file` 读全文。

2. **解析**：用 `python_exec` 写一次性解析脚本，输出到目标文件。
   - 脚本建议：读源文件 → `json.loads`/`re` 解析 → 规范字段 → 写 `jsonl`（每行一条）
   - 文件路径用绝对路径，中文/撇号路径交给 Python（避免 shell 转义）。

3. **入库/落盘**：
   - 结构化数据 → `{工作目录}/data/xxx.jsonl`（或项目约定目录）
   - 关键：**把落盘路径记到记忆**，下轮任务直接用，不再重新定位。

4. **写记忆**：用 `save_memory` 工具（框架记忆）或 `/记` 命令：
   - 记：数据源、落盘路径、解析要点、下次增量抓取策略。
   - 例如：「崩铁角色数据在 D:/data/roles.jsonl，源 BWIKI（反爬用 Referer），每日增量抓取」。

5. **（可选）发邮件汇报**：用 `email_send` 工具一步发送：
   - `to` 收件人、`subject` 主题、`body` 正文（自动处理中文/特殊字符，无需手工令牌流程）。
   - 汇报内容：本次抓到 N 条、落盘路径、关键结论。

**收尾自检**：✓ 数据已落盘 ✓ 路径已记记忆 ✓ 汇报邮件已发（如需）✓ 下次抓取策略已定。

## 模板 2：知识库检索（kb_recall）

适用：不确定「以前整理过的资料在哪」时，先检索而不是重新探索。

1. 先用 `memory_recall`（框架记忆）查：关键词=主题/项目名/日期。
2. 若记忆里没有 → 检查约定的数据目录（如 `D:/data`、项目 `data/` 下）：
   `shell` 跑 `ls`/`find` 找 `*.jsonl`/`*.json`/`*.md`。
3. 找到后用 `read_file` 读结构（前几行即可确认 schema）。
4. 把确认的路径补记到记忆，避免下次再找。

## 模板 3：长任务收尾自检（task_finalize）

适用：任何多步长任务（>3 步）结束前，直接调用 **`task_checklist` 工具**逐项自检：

- [ ] 所有产出文件已落盘、路径明确（可被下次引用）
- [ ] 记忆已更新（save_memory / kb_save：新数据源/新路径/项目状态）
- [ ] 需要通知用户的事已用 `email_send` 发出（或明确决定不发）
- [ ] README/索引/元数据（若项目有约定）已同步
- [ ] 任务看板（若用过 task_board）已全部标 done

有未完成项先补齐再给最终总结。规则 13 已写入系统提示，长任务默认强制走此自检。

## 模板 4：会话恢复（session_resume）

适用：收到「继续」或新会话要续做旧任务时：

1. 若当前会话有「📌 会话现场恢复」注入块 → **直接按它继续**，不要重新探索环境。
2. 没有注入块时：`memory_recall` 查上次记录（数据路径/脚本名/进度）。
3. 再确认关键文件存在（`read_file` 或 `ls`），然后接着做。
